Each fn has its own unique type fn(i32) -> i32 {add_one}. The address is known at compile time, so nothing is stored — calls are direct and inlinable.

Coercing the item to fn(i32) -> i32 erases the unique type: now the address is stored at runtime and the call becomes indirect.

The "pointer to the implementation" is not in the data. It is the operand of the call instruction, chosen from the closure's unique type at compile time. The callee frame needs no bytes: apply::<Closure0> is a copy generated only for this closure, and a different closure would get its own apply::<Closure1>. With --release the whole chain is usually inlined to mov eax, 6. &self points at a ZST, so nothing is read from it and the optimizer drops it.

0 BF: Fn / impl Fn: the code is chosen by the type at compile time. Direct call, can be inlined.
8 Bfn(i32) -> i32: the code is chosen by a value (an address) at runtime. Indirect call through a register.
16 B&dyn Fn / Box<dyn Fn>: the code is chosen by a value (data + vtable) at runtime. Indirect call through the vtable.

mut lets you change the value of p, not its type. A 0-byte p has nowhere to record which closure it holds, so a runtime choice needs bytes. Both bodies always stay in .text, and the call becomes call [rbp-8]. Closures that capture data cannot become fn pointers. Use Box<dyn Fn> for those (16 B). Special case: if c { |x| x+1 } else { |x| x+2 } compiles, because LUB coercion turns both non-capturing closures into fn(i32) -> i32 (8 B).

A trait is a property of a type (Closure0: Fn). It is not a type a local variable can have. Different Fn implementations have different sizes (0 B, 4 B, 24 B…), so the frame could not reserve a slot for "any of them". A Java-style interface variable in Rust is Box<dyn Fn> / &dyn Fn. Java does the same thing implicitly: every object variable is a heap pointer plus vtable dispatch.

size_of::<T>() vs size_of::<&T>()

8 B T: Sized → &T is a thin pointer. It is 8 bytes whether T is 0 B (ZST) or 920 B (Struct2) — the size of T is in the type, not in the pointer.
16 B T: ?Sized (str, [T], dyn Trait) → &T is a fat pointer: ptr + metadata. Metadata is len for slices/str and vtable ptr for trait objects.
T > 8 B? Passing &T copies 8 B instead of the whole value. For T ≤ 8 B (u8, bool, u64, Point) a reference is the same size or bigger than the value itself — pass by value.
1 cell = 1 byte · 64 bytes per line ptr len vtable ptr fields of T padding

Pointer metadata never depends on T's size: &[i32; 3] stays thin (len 3 is in the type), while &[i32] needs a runtime len. A dashed tail means T is unsized: its size is only known at runtime (size_of_val).
